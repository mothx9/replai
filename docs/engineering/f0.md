## Before and after

| Boundary | Baseline | Refounded source |
| --- | --- | --- |
| Public Rust | Editor/EditError/Prompt/Theme/Role portable; Interaction/Event/Error Linux-gated | All types portable; Linux acquisition methods keep exact signatures |
| Interaction | Terminal mixed editing/event policy with descriptors and polling | Private deterministic Engine owns editor/surface and returns semantic effects |
| Input | Decoder keys interpreted in Linux Terminal | VT recognition, compatibility keymap, normalized Input/EditCommand/Request |
| EOF | Physical read EOF and Ctrl-D handled in terminal policy | TransportEof distinct from DeleteOrEof request in engine |
| Layout | Vec of escape-coded row strings | Logical text/style runs, cursor/end cell coordinates |
| Render | Linux redraw/erase/write functions | Renderer transitions to protocol-independent mutations |
| Output | Linux erase/write/redraw transaction | Engine validation/coordination, renderer effects, VT encoding, transport execution |
| Lifecycle | One Terminal owned termios and all interaction state | Resource owns modes/FDs/lease; generic VT driver owns protocol lifecycle; Engine owns interaction lifecycle |
| C binding | Public Rust façade adapter | Unchanged adapter, record layout and symbol set |

The module graph and inventories are in the architecture source-owner table.
Only `system.rs` uses rustix, FDs, termios and process-global exclusion; the public
Linux acquisition bridge imports AsFd. `terminal.rs` uses a generic transport
and its compatibility clock. Editor, normalized actions, engine and renderer
import neither system/protocol APIs nor a scheduler. `presentation` has only
legacy public Theme wrappers for environment/VT access; layout itself is logical.

No unsafe code, dependency, framework, public driven API or new system backend was added.
The existing real-PTY output-failure test was retained and adapted to the moved
resource field, not deleted. Existing core and PTY tests remain authoritative.

## Executable observations

Clean full qualification at `/tmp/replai-f0-clean` (exit 0) used the actual
release C artifacts, staged headers/pkg-config and independent consumer directory
with repository reads denied by Landlock. Observed:

- C/Rust record sizes, alignment, offsets, tags and ABI version compare exactly.
- Static and shared C consumers execute the existing C01–C15 PTY scenarios;
  exact termios restoration, paste cleanup, completion, Unicode, resize and
  external-output draft preservation remain asserted by the existing oracle.
- Caller lifecycle fixture: 128 owners, 384 open/close cycles, FD count 8 before
  and 8 after; caller FDs valid and termios equal on all 384 closes.
- Multiline UTF-8 copy: exact required byte count 9; too-small destination has
  no partial write. Invalid UTF-8/ranges/grapheme splits preserve text/cursor.
- Memcheck 3.22.0: static/shared lifecycle fixtures and shared C PTY scenarios
  exit successfully with 0 errors and 0 bytes in 0 blocks at exit.
- Header C11/C++17 compiles under warnings-as-errors; C++ symbol smoke executes.
  Dynamic exports match the schema; shared loader resolves the staged library,
  static consumer has no shared REPLAI dependency; metadata has no author path.

Deterministic engine/virtual transport conformance exercises the same production
engine and generic VT driver without a system terminal. Structured text/edit
input and VT bytes both reach `é界!🌍`, cursor cell `(0,10)`, then identical
Submitted events. Other observations include exact history draft/cursor return,
atomic rejection, completion replacement, normalized multiline paste, safe-output
mutations, resize, redraw, EOF versus DeleteOrEof, interruption and reopen.
Two independent virtual terminals coexist. Injected read/write/setup/restore
failures prove engine closure, cleanup attempts and retry on drop.

The Linux real read-only-output fault test independently observes saved termios
restoration and paste disable through the surviving TTY descriptor. Existing
PTY tests retain actual input, failure, unwinding and process-exclusion coverage.

## Forward structural questions and deliberate debt

| Next investigation | Executable architectural seam |
| --- | --- |
| F1: can three façades share one engine? | Both direct normalized transitions and the VT session driver use Engine; public tier methods remain undecided. |
| P0: separate costs? | Decoder, keymap, editor, Frame construction, Renderer transition, VT encode and transport are distinct internal calls. No benchmark result is claimed. |
| P2: replace redraw? | Renderer owns the previous frame and returns mutations; resources and Engine input policy do not serialize frames. |
| P3: replace polling? | Engine takes input/resize with no clock or wait; the current driver alone chooses timeout/expiry. |
| I5: different keymaps? | Compatibility binding maps recognized keys to normalized requests/edit commands; decoder does not call Editor. |
| X1/X2: another OS? | Byte transport can back the VT driver; structured events and non-VT mutation execution can bypass it, using the same engine/layout. |

Deliberate debt: the internal byte transport is not a final universal event API;
Theme retains its public VT sequence helper; only existing color facts are
resolved, not F2 capabilities; the Linux lease remains process-wide; the VT
façade retains one-byte reads and periodic resize checks. String/grapheme scans,
logical-run/effect allocations and append-or-redraw remain unoptimized private
choices. Unicode cell width depends on terminal behavior; the VT oracle does
not establish every emulator's joined-emoji or resize-reflow behavior.
